# Claude Quick-Prompt Pet

Маленький десктопний віджет для Windows: анімований пет у куті екрана, який приймає промпт
і показує, що Claude робить прямо зараз. PowerShell 5.1 + WPF, без жодних залежностей —
ні Node, ні збірки, ні пакетів.

> **Цей файл — орієнтація.** Щоб документи не розповзлися:
> тут — *що це і як запустити*; у [CONTEXT.md](CONTEXT.md) — *чому воно так і на що не
> наступати* (інтеграції з Claude, розбори багів); у [DESIGN.md](DESIGN.md) — *макет,
> токени, стани* і правило якоря, яке легко зламати, не помітивши.

## Що працює зараз

| | |
|---|---|
| **Enter** | headless `claude -p`: **жодного вікна не відкривається**. Живий статус, а по завершенні — картка з повною відповіддю. Це шлях «не тягни мене в додаток» |
| **Ctrl+Enter** | свідомо відкрити справжній чат у додатку з цим промптом. **Вікно додатка підніметься** — у `claude://` немає фонового маршруту |
| **Open in app** | з'являється лише на картці чату, створеного через Ctrl+Enter: у headless-прогону немає сесії, яку додаток здатен відкрити |
| **Наведення** | поле вводу відкривається, лише якщо затриматись на петі на `hoverDelayMs` (за замовч. 1.2 с). Клік відкриває одразу, перетягування — ніколи |
| **Кнопка камери** | з'являється ліворуч від пета на ховері. Знімає екран і чіпляє знімок до **наступного** промпта — обидва шляхи відправки несуть його однаково. Чип у полі вводу: ховер — прев'ю, клік — від'єднати |
| **Тягнути пета** | перенести віджет, позиція зберігається |
| **Права кнопка** | міні-меню: розмір віджета, окремо розмір інпута, скид, закрити |
| **Ctrl+колесо** | масштаб усього віджета 0.6–2.5 |
| **Ctrl+Shift+колесо** | масштаб **тільки інпута**, незалежно від пета |

Пет реагує на стан задачі: `idle` → `working` → `done` / `blocking`. Колір підсвітки
під ногами дублює стан, тож його видно і коли віджет згорнутий.

## Запуск

```bash
powershell.exe -NoProfile -ExecutionPolicy Bypass -STA -File pet-icon.ps1
```

Штатно — ярлик `Claude Pet` на робочому столі → `run-pet.bat` → `run-pet.vbs`
(запускає PowerShell приховано, **без жодного консольного вікна**).

Демо-стенд повної оболонки з картками, окремо від віджета:

```bash
powershell.exe -NoProfile -ExecutionPolicy Bypass -STA -File pet-visual.ps1 -Demo
```

## Контракт з артом

Рендерер читає **тільки** теку PNG і маніфест — більше нічого:

```
sprites/frames/
  manifest.json          # frameMs / loop / кількість кадрів на стан
  idle/01.png 02.png
  working/01.png 02.png
  done/ hover/ input/ thinking/ blocking/
```

**Заміна персонажа = підміна PNG-файлів. Код чіпати не треба.**
Кадри зберігаються в нативній роздільності; масштабує рендерер.

Розмір і тип арту теж належать арту, а не коду — два **необов'язкові** поля маніфесту:

| Поле | Що робить |
|---|---|
| `displayHeight` | висота персонажа на екрані (DIP). Ширина рахується з аспекту самого кадру, тому розтягнути арт неможливо. Хіт-бокс і тінь під ногами виводяться з неї |
| `pixelArt` | `true` → `NearestNeighbor` (піксель-арт лишається чітким), `false` → `HighQuality` (згладжений арт не розсипається на сходинки) |

Без них вирішує XAML (44×44, `NearestNeighbor`) — старі маніфести рендеряться як раніше.

### Таймінг: `frameMs` скаляр або масив

`frameMs` — або одне число на весь стан, або **масив по кадрах**:

```json
"idle": { "frameMs": [2600, 110, 180, 110], "loop": true, "frames": 4 }
```

Масив існує заради кліпання. Рівний двокадровий цикл на людському обличчі читається не як
«дихає», а як «засинає»; живе кліпання — це ~2.6 с відкриті очі проти ~0.1 с закриті.

Три правила нормалізації, щоб маніфест не міг поломати таймер:

- скаляр — це просто рівний випадок масиву, шлях виконання один;
- коротший за `frames` масив тримає своє останнє значення, а не падає в нуль;
- `0` всередині масиву піднімається до 16 мс — інакше це таймер з нульовим інтервалом.

Стан анімується, лише якщо кадрів більше одного **і** хоч одна тривалість ненульова, тож
`hover` і `input` з `frameMs: 0` лишаються статичними кадрами, як і були.

### Збірка кадрів з VN-арту

Арт візуальних новел (tachie) — це поза плюс окремий шар обличчя/рота на тому самому
полотні, часто 1000–2000px із величезними прозорими полями. `sprites/build-character-frames.ps1`
зводить його до контракту вище за маппінг-файлом
([шаблон](sprites/character-mapping.example.json)):

```bash
powershell -NoProfile -ExecutionPolicy Bypass -STA -File sprites/build-character-frames.ps1 -SourceDir sprites/kurisu-source -ListSource
```

```bash
powershell -NoProfile -ExecutionPolicy Bypass -STA -File sprites/build-character-frames.ps1 -SourceDir sprites/kurisu-source -MappingPath sprites/kurisu-source/mapping.json
```

**Дві пастки, що коштували окремого заходу.**

Перша — **реєстрація**. Пози не мають спільного розміру полотна («руки счеплені» 360px
ширини проти 480px у «руки вниз»), тому один прямокутник кропу по сирих файлах виходить
за межі вужчих. Але вирівнювання по alpha-bbox кожного кадру — гірше й підступніше: у пози,
зрізаної по стегнах, межі коротші, і персонаж «змінює зріст» між станами. Полотна рипу
вже зреєстровані між собою — саме вони й є вирівнюванням (`anchor`, за замовч. `center-top`),
а alpha лише вирішує, скільки спільних полів зрізати потім. Окрема поза підтягується
через `"nudge": [dx, dy]`.

Друга — **різний зум при однаковій висоті полотна**. У рипі Steins;Gate всі `bs*`-файли
мають 624px висоти, але поза `c` намальована більшою й зрізана по стегнах, тоді як `a` і `b` —
в одному масштабі. Жодна реєстрація цього не виправить. **Перевіряй перед маппінгом:**
наклади дві пози 1:1 і подивись на голови. Збігаються — можна змішувати; ні — бери одну сім'ю поз.

**Ліцензійно.** Рипи з ігор/аніме — чужа власність, і генеровані з них кадри теж. Щоб вони
фізично не могли потрапити в репо, персонаж не перезаписує `sprites/frames/` (вона відстежується
гітом і тримає MIT-плейсхолдер), а живе у власній теці й підключається через `framesDir`
у `config.json`:

```json
{ "framesDir": "sprites\\kurisu-frames" }
```

У `.gitignore` є обидва шаблони: `sprites/*-source/` (вихідний рип) і `sprites/*-frames/` (зібране).

Поточний арт — **плейсхолдер** (кіт «Pixel Buddy» з
[claude-code-mascot-statusline](https://github.com/TeXmeijin/claude-code-mascot-statusline), MIT).
Цільовий вигляд — маскот-хмара з терміналом замість обличчя; 16×16 плоскою палітрою
його градієнти не намалюєш, під фінал потрібні растрові кадри ~64px з альфою.

## Як агенту перевіряти зміни

Доступу до десктопу не треба: **вікно рендериться саме в себе** через
`RenderTargetBitmap.Render($root)`, далі композит на темний фон. Для `pet-icon.ps1` це
робиться тимчасовою копією `pet-icon.selftest.ps1` у теці проєкту (щоб `$PSScriptRoot`
лишався валідним), яка після прогону видаляється.

**Скріншотів мало.** Найгидкіший баг цієї сесії на них виглядав нормально — знайшла його
тільки програмна проба стану (`panel.Visibility`, `ScaleY`, `Opacity` у файл). Перевіряй
стан, а не тільки картинку.

Три пастки самого харнеса, які дають **фальшиві** баги, — описані в
[CONTEXT.md](CONTEXT.md) (розділ про перевірку без десктопу). Не лови їх удруге.

## Що далі

1. **Персонаж** замість кота-плейсхолдера — найпомітніша зміна, коду не потребує.
2. **Вшити оболонку з картками** з `pet-visual.ps1` у віджет: hover-pill, морф pill→input,
   переписування заголовка в «Locate …». Це переписує UI, тому свідомо окремим кроком.
3. **Діалог усередині віджета** — найбільша різниця з референсом: там бот ставить
   уточнювальне питання і користувач відповідає в тому ж баблі. Зараз потік one-shot.

## Обмеження, про які варто знати

- **Додаток не має фонового режиму.** Кожен маршрут `claude://` навігує головне вікно
  (`bR(route, mainWindow)`); API, щоб додаток обробив промпт, не показавшись, не існує.
  «Оброблено в додатку» і «вікно не з'являється» — взаємовиключні. Без вікна працює
  тільки headless.
- **Headless-прогін у список додатка потрапляє — але на вимогу.** Сам собою він там не
  з'являється (стор читається лише на старті, вотчера немає). Кнопка «Open in app» шле
  `claude://resume?session=<uuid>`, і застосунок всиновлює CLI-сесію через власний
  `importCliSession` — наживо, без перезапуску.
- Тільки Windows: WPF + `claude://` URI-схема з реєстру.
- Скрипти мусять лишатися **чистим ASCII** — PowerShell 5.1 читає `.ps1` без BOM як ANSI.
  Гліфи йдуть через XAML-ентіті або `[char]0x…`.
- У розгорнутому стані смуга обабіч пета належить прозорому вікну і теж ловить кліки.
  Зникає при згортанні.
